# Guideline: Objekt-Idee

## Ziel
Verfasse mit dem User eine neue Objekt-Idee. Wenn es noch Unklarheiten vor allem wegen Funktionsweise gibt, nachfragen. Anders bei Dingen, die sich von selbst ergeben, wie z. B. dass ein „Feuer-Schwert“ aggressiv ist.

## Grundprinzip
Objekt-Ideen beinhalten Idee und eine konkrete Funktionsweise, ohne Implementierungs-Details. Das heißt: Es soll klar sein, was das Objekt tut und warum es interessant ist, aber noch nicht, wie es technisch im Code integriert wird.

## Template

### 1. Rolle
Was ist dieses Objekt im Spiel?

### 2. Kernwirkung
Was macht es grundsätzlich?

### 3. Features / Identität
Warum ist es einzigartig, welche Nuancen hat das Objekt als Feature?
Wie steht es zu anderen Objekten, z. B. Alchemie, Loot, Gegner-Effekte oder Spielstil?

### 4. Spielwert
Warum sollte der Spieler es wollen, vermeiden, nutzen oder finden?

### 5. Stil / Ton
Ist es mystisch, aggressiv, defensiv, seltsam, gefährlich, charmant, rätselhaft?

## Beispiel
```md
### Objekt-Idee: Flammender Amulettsplitter
- Rolle: Ein starkes, seltenes Relikt mit Fokus auf aggressive Kombinationen.
- Kernwirkung: Beim kritischen Treffer entzündet es den Gegner kurzzeitig und steigert danach für eine kurze Zeit den eigenen Angriffsschaden.
- Features / Identität: Es ist kein bloßer Schadensbonus, sondern ein "Tempo + Risiko"-Objekt, das den Spieler in kriegerische, aggressive Spielzüge zieht.
- Spielwert: Motiviert den Spieler, kritische Treffer gezielt zu planen und macht das Relikt in schnellen Durchläufen besonders attraktiv.
- Stil: heiß, kriegerisch, gefährlich, aber lohnend.
```

## Kurz-Checkliste
- [ ] Die Rolle des Objekts ist klar.
- [ ] Die Kernwirkung ist verständlich.
- [ ] Die Idee hat einen erkennbaren Charakter.
- [ ] Der Spielwert ist deutlich.
- [ ] Die Beschreibung bleibt auf Idee und Funktionsweise fokussiert, nicht auf Implementierung.
